> 状态：设计稿（未落地定价策略，未宣称 GA）
> 日期：2026-11-18
> 基线：HEAD `ce8cb3149` + 本批 MCP 服务端骨架
> 关联：`docs/product/itsm-commercial-capability-contract.md`、`plans/open-source-commercialization-2026q3-blueprint.md`

## 1. 为什么是托管订阅，不是卖文件

业界对 Skill / MCP 变现的实测结论高度一致：**卖文件是最差模式**。

| 模式 | 形态 | 定价 | 护城河 | 判定 |
|---|---|---|---|---|
| A 卖文件 | 交付 SKILL.md / server 二进制 | $5–200 一次性 | 无（首次下载即失控） | 差 |
| B 定制服务 | 按客户逐个实施 | $1.5K–5K 一单 | 部分 | 一般 |
| C 托管订阅 | 运行时 + 权限 + 迭代 | $20–499/月 | 完整 | 胜出 |

本设计采用 **C**，并把 B 作为前期现金流入口（服务先行、产品在后）。

关键差异点：Skill 卖的是「知识」（零复制成本），MCP 卖的是「可信连接」（需鉴权、审计、SLA、可观测）。因此**收入锚点在 MCP 托管服务，Skill 作为订阅附赠的领域工作流**。

## 2. 落在既有能力上（本批已具备的骨架）

商业化不新建机制，全部复用既有单一源：

| 商业要素 | 既有承载 | 状态 |
|---|---|---|
| 商品模型 | `marketplace_items`（`price`/`is_free`/`type`/`capabilities`/`required_permissions`/`config_schema`） | 已有 |
| 交付门禁 | `marketplace.SkillInvocationEntitlement`（上架 + 安装才可调用） | 已有，本批已接入 MCP |
| 安装/卸载 | `marketplace.InstallItem` / `UninstallItem`（卸载即撤权） | 已有 |
| 工具面 | `internal/services.ToolRegistry.ListToolsForTenant` | 已有，本批已投影为 MCP tool schema |
| 权限链 | `ai.Service.ExecuteTool`（Gate 2 RBAC + Gate 2.5 主体零信任 + 写工具审批 + 审计） | 已有，本批已复用 |
| 主体准入 | `authz.Registry.AuthorizePrincipal`（DB 策略 `AllowedPrincipals`），由执行链 Gate 2.5 按工具自身 `resource:action` 判定 | 已有，本批复用（未另设通道码） |
| 审计 | `ToolInvocation`（含 `invocation_id`、`approval_state`、`role_snapshot`） | 已有 |

**结论**：商业化需要的「计价 + 交付 + 权益 + 审计」四件套均已在仓库内，MCP 服务端只是把它们接成一个协议出口。

### 2.1 为什么只新增一个权限码

本批只加 `mcp:read`（通道准入），**刻意不加 `mcp:invoke`**：

- 调用面的主体权限由既有执行链（`ExecuteTool` 的 Gate 2.5）按**工具自身的 `resource:action`** 逐个判定，粒度比通道级一刀切更细 —— service 主体可被放行只读工具、仍被拒写工具。
- 若在 MCP 层另设通道码再判一次，会形成**两套主体判定**：更粗的那套会先放行、把细的那套变成摆设。
- 附带：`mcp:invoke` 无路由引用会成为死码，触发 C.6 反向死码守卫（本批实测该守卫抓出此问题并据此收窄设计）。

**这是一次由门禁驱动的设计收窄**：先写出的实现更粗，被既有守卫抓住后改为复用单一源。

## 3. 套餐分层（设计稿，未定价发布）

三档，覆盖从试用到企业落地。**价格待商业决策后填入 `marketplace_items.price`**，本文只定义权益边界。

### 3.1 Community（社区版）

- **价格**：免费（`is_free=true`）
- **交付物**：只读工具面（事件统计、CMDB 读取、知识检索、工单查询）
- **调用限额**：建议 100 次/天/租户
- **主体**：`human`（登录用户）或 `agent` 角色
- **写操作**：不开放
- **用途**：开源引流、开发者体验、试用转化

### 3.2 Team（团队版）

- **价格**：按租户月费（设计区间 $29–99/月，**待定**）
- **交付物**：全部只读工具 + 有限写工具（如建单、补备注），写操作走审批流
- **调用限额**：建议 5,000 次/天/租户
- **主体**：`human` / `agent` / `service`（service 需管理员在权限策略显式放行）
- **附加**：MCP 通道 SLA、调用审计导出、成本可见性

### 3.3 Enterprise（企业版）

- **价格**：年费（设计区间 $3,000–20,000/年，**待定**）
- **交付物**：全部工具面 + 私有化部署选项
- **调用限额**：协商，或按包量
- **主体**：全部，含 `service` 主体 + 企业 IdP（走 MCP Enterprise-Managed Authorization 扩展）
- **附加**：SLA（可用性承诺）、审计留痕导出、专属支持、私有源构建

## 4. 权益矩阵（实现口径）

| 能力 | Community | Team | Enterprise |
|---|---|---|---|
| 只读工具面 | ✅ | ✅ | ✅ |
| 写工具 | ❌ | ✅（需审批） | ✅（可配免审） |
| service 主体调用 | ❌ | ✅（需策略放行） | ✅ |
| 免审批写操作 | ❌ | ❌ | ✅（显式配置） |
| MCP 协议版本跟进 | 社区版 | ✅ | ✅ |
| 调用审计导出 | ❌ | ✅ | ✅ |
| 私有化部署 | ❌ | ❌ | ✅ |

### 4.1 权益如何落到代码（不新增第二套判定）

权益收敛点只有一个：**`marketplace_items` 的商品记录**。

```
工具可见性 = 商品已上架 ∧ 租户已安装 ∧ 商品.capabilities 含该工具
授权放行   = authz 运行期策略的 AllowedPrincipals 含调用主体
动作权限   = ai.Service.ExecuteTool 内的 Gate 2 / Gate 2.5（按工具 resource:action）
```

三处判定各管一件事，**不互相替代**：

- **权益**决定「买没买」（商业维度）
- **授权**决定「这个主体能不能走 MCP 通道」（主体维度）
- **动作权限**决定「这个主体能不能做这个动作」（资源维度）

MCP 服务端本批已把这三者接齐（`handlers/mcp/service.go`）。

### 4.2 套餐差异的实现位置

| 差异 | 实现位置 | 是否需改代码 |
|---|---|---|
| 工具面差异 | 商品 `capabilities` 字段（不同套餐挂不同商品） | 否 |
| 调用限额 | 需新增计费/配额读面 | 是（独立批次） |
| 免审批写操作 | `authz` 策略 `RequiresApproval`/`MinApprovals` 运行期配置 | 否 |
| service 主体放行 | `authz` 策略 `AllowedPrincipals` 运行期配置 | 否 |
| SLA / 支持 | 非代码，属交付承诺 | 否 |

**关键**：三档套餐的绝大部分差异是**配置**而非代码。只有「调用限额」需要一次独立开发（可复用既有 AI 配额设施）。

## 5. 商业化路径（从零到第一笔收入）

### 阶段 1 · 服务先行（0→1 单，验证 PMF）

- 用**定制实施**接 1–2 个真实客户（模式 B），收费方式为项目费 + 年费
- 交付物：私有化部署 ITSM + MCP 通道 + 2–3 个垂直工具面（如「告警→建单→关联 CMDB」）
- 目的：拿到真实需求，暴露边界 case，把重复模式沉淀成模板
- **不宣称 GA**：市场页口径保持「能力目录 / 持续更新」

### 阶段 2 · 产品化（模板 → 商品）

- 把阶段 1 的重复模式固化为 `marketplace_items` 商品
- 上架到应用市场：`type=skill`（工作流）/ `type=connector`（连接器）；MCP 通道本身作为平台能力，不单独售卖
- 定价写入 `price`，权益写入 `capabilities` / `required_permissions`

### 阶段 3 · 订阅化（规模）

- 开放自助订阅：选套餐 → 装商品 → 即刻用 MCP
- 计费/配额读面落地（复用 AI 配额设施）
- 渠道：官网 `marketplace/` 频道已是获客入口，可挂「开通试用」

### 阶段 4 · 生态（12–18 个月窗口）

- 把工具面开放给第三方开发者（Skill/MCP 生态）
- 平台抽成模式（对标 MCP 生态的 20–30% 惯例）
- **风险**：通用层可能被大厂收编，差异化只剩垂直深度 + 企业合规

## 6. 风险与红线

| 风险 | 应对 |
|---|---|
| 通用 connector 层被云厂商免费收编 | 只做垂直场景（ITSM 运维闭环），不做通用 MySQL/Redis |
| service 主体权限面过宽 | `AllowedPrincipals` 默认 `["human"]`，须管理员按工具码逐个显式放行；本批未另设通道级判定码，主体判定全部下沉执行链 |
| MCP 通道成为绕过市场交付的旁路 | 权益门禁在列举与调用两处都生效（本批已有契约测试锁定） |
| 采购要求过审计 | 复用既有 `ToolInvocation` 审计 + `authz` 运行期策略，提供导出 |
| 过早宣称 GA | 对外口径保持「能力目录 / 持续更新」，与官网既有口径一致 |
| ICP 备案未完成 | 暂不做面向境内付费主体的正式签约；官网不加备案号 |

## 7. 下一步（按优先级）

1. **P0**：为 1 个真实客户做 MCP 接入（阶段 1）——验证 PMF 的唯一方式是做出来给人用
2. **P1**：调用限额读面（配额治理），复用 `AIQuotaService`
3. **P2**：市场管理端支持 MCP 商品上架（当前商品类型枚举是 connector/skill/plugin，MCP 通道本身不需新增类型）
4. **P3**：service 主体对具体工具码的放行做成管理端可配（当前需改 DB 策略 `AllowedPrincipals` 或 seed）
5. **待决**：具体定价数字（本文只给设计区间，不擅自定价）
