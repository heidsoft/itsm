# 语义：这是**上限**，只允许下降，不允许无声明增长。
#   current > baseline  -> FAIL（必须在同一个 commit 里显式上调基线并说明理由）
#   current <= baseline -> PASS（下降是好事，不会失败）
#
# 为什么要有反向检查：正向检查只在「CLI 引用了后端没有的路由」时失败，反方向
# 从未被校验。结果是一整族后端能力可以带着零 CLI 覆盖率上线而所有门禁全绿——
# 云/发现（cloud accounts/services/resources + discovery sources/jobs/results/

# 目标不是 100% 覆盖（存量缺口是产品决策，不是构建门禁），而是**不许静默回退**：
# 新增后端路由必须同时接入 CLI 命令，否则本检查变红。
#
# 计数口径：与 scripts/check-route-drift.mjs 完全一致——后端从 itsm-backend/router
# 与 itsm-backend/handlers 两个目录静态扫描（变量→分组前缀链式解析），CLI 侧取
# dist/agent/registry.js 里每条命令声明的 endpoints（`:param` 归一为 `{}`）。
# 该口径是启发式的，会有噪声（handlers 目录下非路由注册的误报），但它是确定性的，
# 所以作为棘轮有效。**上调前必须按脚本口径实测，不要凭直觉改数。**
